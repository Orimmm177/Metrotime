01概览：把上一动作块的计算带到下一块

C³ache 将 Fast-WAM 动作专家在某个去噪步产生的整栈残差保留到后续 inference chunk，在相同去噪步直接加到新的输入 token 上，跳过全部 DiT blocks。它是无需训练的计算复用方法：模型仍生成 32 步动作块，仍执行 10 次采样更新，也仍处理当前视觉观测；节约的是动作专家内部重复的 attention 与 FFN 计算。论文 §3–4，pp.4–8

最值得记住的结果不是一个通用倍数，而是两个平台各自的精度—速度取舍。在论文 A100 80GB、Fast-WAM 6B、10 步采样、horizon 32 的统一设置下，LIBERO 的 [0,7], τ=0 达到 2.51×、成功率 97.10% 对 96.90%；RoboTwin 的 [0,6], τ=0 为 1.84×、成功率 90.35% 对 91.40%。同样的激进 [0,7], τ=0 在 RoboTwin 却下降 15.55 个百分点。精度与 batch 未报告；计时为所有评测 episode 的完整模型推理管线累计墙钟口径，不能换算成机器人控制频率。表1 p.7；表2 p.8；§4.1 p.7

02问题定义与三条时间轴

闭环任务不是只调用模型一次。每个控制周期 cc，策略读取新的上下文 ctxc\mathrm{ctx}^{c}，输出未来 HH 个动作组成的 xcx^c；执行其中一部分后环境改变，再生成 xc+1x^{c+1}。在每个动作块内部，flow matching 又需要 KK 次逐步去噪。一个包含 CC 个块的 episode 因而会调用动作专家约 CKCK 次。§3.1 p.4

轴 含义 本文已知与未知
环境周期 cc 新观测、重规划、执行动作块前缀 每块实际执行多少动作、实际控制 Hz 未报告
去噪步 kk 同一块中由噪声积分到动作 实验为 10 次更新；缓存表用 0–9 下标
动作位置 jj 一个输出块中的未来控制点 horizon 32；不等于每次执行 32 步
连续流时间 tt 论文定义的噪声到数据路径 从 0 到 1；不要与环境时间混淆

本报告将动作张量写为 xc∈RH×Dax^c\in\mathbb{R}^{H\times D_a}，隐藏 token 为 h0,hL,R∈RH×dah_0,h_L,R\in\mathbb{R}^{H\times d_a}，batch 维省略；DaD_a 是动作维数、da=1024d_a=1024 是动作专家隐藏维。前者取决于机器人，后者由本文 §4.1 指定。代码确认 Fast-WAM 一个动作位置对应一个 token，但 C³ache 自身未公开张量日志。

任务目标是在尽量保持成功率的同时降低累计推理耗时。关键假设是相邻块的行为和观测足够平滑，相同采样阶段的残差仍可近似复用。它不假定所有去噪步相同，也不假定场景一直不变，更没有把未来真实视频当作推理输入。

03架构：Fast-WAM 外壳与 C³ache 改动

Fast-WAM 已在训练中保留视频建模，但在动作推理时去掉未来视频合成。当前观测经过 VAE 与视频专家的一次 prefill，产生供动作专家读取的视频表示/KV；动作专家从高斯噪声出发，通过 MoT joint attention 把当前视频、动作 token 及条件信息结合，预测 flow velocity。C³ache 在这个动作专家外面加入“是否执行 DiT 整栈”的分支。§2.1、§3.1、§4.1

此图为据论文与骨干接口绘制的讲解示意。实线观测路径进入实际执行的 DiT，虚线跨块路径提供旧残差；它没有把 h₀ 直接画成当前视觉观测的编码。

模块如何协作

视觉与条件编码。 VAE 编码当前图像，视频专家 prefill 构造本 chunk 的逐层 KV。这些 KV 可以在本块的多个去噪步共享，但不是 C³ache 的跨块残差 cache。论文明确把 VAE 和 prefill 列为不缓存且纳入计时的成本。骨干代码另将语言编码与本体状态 token 作为 context 传入；C³ache 论文没有详细重述相机、语言、本体状态的处理参数。

动作嵌入。 当前 noisy action 被投影为 h0h_0；去噪时间控制 adaptive normalization。即使命中缓存，仍重新做动作 embedding，因此沿采样轨迹变化的输入不会整体冻结。

MoT / DiT 整栈。 完整计算时，动作 query 读取视频 KV 与动作 KV，并进行后续条件 attention、FFN 和残差更新。缓存对象是整个 LL 层产生的总增量，不是某层 KV、attention map，也不是最终动作或 velocity。

Rkc=hLc,k−h0c,kR_k^c=h_L^{c,k}-h_0^{c,k}

该式是论文式(3)、(6)的带索引写法。RR 与输入/输出隐藏序列 shape 一致，所以重建仅需逐元素相加。完整计算后的输出头仍执行：

vkc=Head(h0c,k+Rkc)v_k^c=\mathrm{Head}(h_0^{c,k}+R_k^c)

这是式(4)。缓存命中时将 RkcR_k^c 替换为先前刷新块 r(c)r(c) 中同一步 Rkr(c)R_k^{r(c)}，得到近似输出；当前 h₀ 和输出 head 都仍计算。若直接缓存 hL 或 v，则会把该阶段的最终隐藏状态或速度固定，连新的 noisy action 的直通项也丢失。论文因此选择 R，但没有给出 R / hL / v 三种缓存对象的成功率对照消融。§3.3 pp.5–6

Scheduler 与执行。 采样器仍执行全部更新，最终 action chunk 还要反归一化、选取前缀、交给控制器，再读取新观测。C³ache 没有蒸馏新模型、缩小 6B 参数量、减少 action token 数，也没有改成一步采样。

一条需要保留的证据分歧：h₀ 究竟包含什么

论文 §3.1 把 h₀ 定义为 noisy action embedding，把视觉条件放在 DiT 的 joint attention；但 §3.3 和图3又称 h₀ 已携带新观测。当前官方 Fast-WAM 的 ActionDiT.prepare 明确使用 tokens = self.action_encoder(action_tokens)，另行构造 context_emb；视觉 KV 在 MoT.forward_action_with_video_cache_tensor 内被读取。action_dit.py L312、mot.py L528

因此，保留 h₀ 只能直接证明保留当前动作迭代量，不能据此证明缓存步充分吸收新视觉观测。若按这个骨干接口跳过所有 block，命中步不会重新读取该步的视频/语言/本体条件；保留完整计算的尾部步仍可读取当前条件并修正动作。这是从已读骨干代码推出的解释，不是已验证的 C³ache 实现行为。未公开的 C³ache 分支是否额外融合观测，仍是复现前必须澄清的缺口。

04缓存生命周期：命中、刷新、失效

C³ache 是预先选定步范围 + 固定 chunk 周期的调度。图2的 cosine similarity 是离线经验分析，不是在线每步计算的命中阈值，也没有动态置信度门控。§3.2–3.3

状态 / 事件 实际含义 证据边界
首块 c=0c=0 所有步完整执行，填充各步残差 §3.3 明确
命中 当前步属于缓存范围，且未到刷新块；读相同 k 的 R 不从 k−1 读，也不按余弦阈值判定
周期刷新 对 τ>0\tau>0，c mod τ=0c\bmod\tau=0 的块完整重算并更新 如 τ=4：块0、4、8刷新
τ=0 首块后残差一直冻结，不再周期刷新 不是关闭缓存，也不能执行模零运算
尾部步不缓存 [0,6] 保留步7、8、9完整算；[0,7] 保留步8、9 表格采用从0开始的下标
场景突变 没有论文定义的自动失效机制 动态刷新是 §5 的未来工作

论文式(8)只写了 c mod τc\bmod\tau，需结合前文补上 τ=0 特例。本报告用以下等价调度表达消除除零歧义；r(c)r(c) 是最近的完整刷新块，SS 是允许缓存的步集合：

r(c)={τ⌊c/τ⌋,τ>00,τ=0r(c)=\begin{cases}\tau\lfloor c/\tau\rfloor,&\tau>0\\0,&\tau=0\end{cases}
h^Lc,k=h0c,k+Rkr(c),k∈S 且 c≠r(c)\widehat h_L^{c,k}=h_0^{c,k}+R_k^{r(c)},\qquad k\in S\text{ 且 }c\ne r(c)

这是解释性改写，原式(7)写 k′k' 与 kk，但本文方法范围明确要求匹配同一步，即 k′=kk'=k。采样器、步数或 noise schedule 改变后，整数 k 不一定对应相同噪声水平，旧缓存不应继续复用。多环境 batch 还需每条 episode 独立缓存；这些是部署约束建议，并非作者已实现的保障。

跟踪一个动作块

以教学配置 S=[0,6], τ=4 为例。块0观测编码后，步0–9依次完整运行；在选中步保存 R₀ 至 R₆。执行动作前缀后进入块1，重新采集观测、重新做 VAE/prefill，并抽取本块的初始动作噪声。步0用新 embedding 加旧 R₀，再经 head 和 scheduler 更新；步1同理读 R₁，直到步6。步7–9完整读取当前条件，得到最终动作块。块2、3继续使用块0的各步缓存；块4完整计算并覆盖缓存。后面“每四块刷新”计数单位是模型请求，不是动作位置、环境步或去噪步。

教学伪代码；不是官方 C³ache 实现
cache = empty_per_episode()
for c in control_cycles:
    observation, context = read_current_inputs()
    video_kv = encode_and_prefill(observation, context)
    x = sample_fresh_action_noise()
    refresh = (c == 0) or (tau > 0 and c % tau == 0)
    for k in range(K):
        h0, conditioning = prepare_action(x, k, context)
        if k in cache_steps and not refresh and cache[k] exists:
            hL = h0 + cache[k]
        else:
            hL = all_dit_blocks(h0, conditioning, video_kv)
            if k in cache_steps:
                cache[k] = copy(hL - h0)
        velocity = head(hL)
        x = scheduler_step(x, velocity, k)
    execute_prefix(denormalize(x))

这里的 copy 表示缓存不能被后续 in-place 更新污染；实际 CUDA Graph buffer、dtype/device 与生命周期需实现者处理。该伪代码不引入论文没有的相似度阈值或误差补偿。

05为什么有效，以及加速上限在哪里

图2，PDF p.5，原始 cos_sim.pdf。作者用 LIBERO 四个 suite 共2000个 episode、29924个 inference chunk，10步采样，对 hL、R、v 做相邻块同一步 cosine similarity 分析。其聚合方式、首块怎样排除、向量展平或 reduction 细节未公开。图中残差平均相似度并非接近1的完美一致；尾部均值下降且标准差上升。§3.2 p.5

直觉是相邻规划周期常在执行同一连续行为，完整网络给输入补上的增量变化较慢；缓存 R 后依然让当前动作状态走直通路径。晚期采样更加决定最终动作细节，跨块差异又增大，所以只缓存前段，把后段留给当前条件修正。这一机制解释与尾部缓存消融相容，但余弦相似不约束残差范数，也不能单独保证闭环安全或误差不累积。

论文 §4.1 写“均值和标准差都下降”，与图2右侧和 §3.2 的标准差上升相冲突；报告以图和 §3.2 为准。C³ache 的 evidence 是平滑轨迹上的经验可复用性，而非关于任意接触、碰撞、遮挡或指令切换的误差上界。

计算预算的解释性分解

设每个块不可省的 VAE/prefill 等成本为 A，每个完整 DiT 栈为 B，每步 embedding/head/scheduler 为 E。M=∣S∣M=|S|，FF 为完整刷新块数量，忽略访存与 cache 写读成本且固定总块数 C：

Tbase=C [A+K(B+E)]T_{\mathrm{base}}=C\,[A+K(B+E)]
Tcache≈C(A+KE)+[CK−M(C−F)]BT_{\mathrm{cache}}\approx C(A+KE)+[CK-M(C-F)]B

这是分析者成本模型，不是论文测量。可缓存步在刷新块仍需完整算；τ=0 且 episode 非空时 F=1。即使跳过大部分 block，VAE/prefill 与其余步骤也不会消失，所以“跳过80%的步内整栈”不等于端到端5倍加速。更关键的是缓存误差可能改变成功/失败时机、episode长度与 C，因此只报累计 wall-clock 不能分离“每次调用加速”和“行为长度变化”。原文没有提供原始秒数、每块分布或成功/失败分层计时。

加速轴 C³ache 的变化
参数规模 不改权重；沿用总6B、动作专家1B
token数量 / 分辨率 不以删 token 或降低图像分辨率为机制
采样更新数 保持10次；命中步仍经过head与scheduler
重复计算 省去选定步在后续块中的整栈attention/FFN
缓存 按同一k保存跨块R；不同于视频prefill KV
调度 手工设置步范围与刷新周期；无动态场景判据

论文在引言称可与块内 step-wise cache 组合，§2.3也强调两个冗余轴；但主实验和消融只列跨块范围/周期，没有叠加 TeaCache 等的配置或效果表，不能把“可组合”说成已验证的额外加速。

06数据、训练与推理接口

数据能支持什么结论

C³ache 不新增训练数据，而是评测已训练的 Fast-WAM。LIBERO 用 Spatial/Object/Goal/Long 四套，每套10任务、500次评测，共2000次；RoboTwin 2.0 用50个双臂任务，每任务 clean/randomized 各20种种子，即每设置1000次、共2000次评测。clean 已随机对象初始位置；randomized 额外改变背景、光照、桌高、相机距离、杂物。§3.2、§4.1 pp.5–7

这些是作者报告的评测 episode 数，不是训练示范数量。本文没有给出 C³ache 使用 checkpoint 的训练总量、混合比例、数据清洗或划分文件。没有原始数据访问，因此不能声称验证过重复轨迹、时间同步或训练/评测泄漏。LIBERO 上用于观察相似度的全套评测又支持了缓存步范围选择；论文未给独立调参集，最优范围的外部泛化仍需另测。

骨干当前 configs/data/libero_2cam.yaml 提供可定位的示例：两路224×224图像横拼为224×448；32个动作搭配9帧视频，动作/视频采样比4；动作7维（6维末端增量及夹爪）、状态8维；min/max归一化。动作坐标系、物理单位仍应依据 benchmark controller 确认。这些是所读骨干配置，不是 C³ache 未披露实验参数的替代证据。

训练如何得到可缓存的骨干

本文的训练步骤是“无”：C³ache 不增加 loss、参数或蒸馏 teacher。其能力来自 Fast-WAM 的视频与动作共同训练。沿当前骨干实现，dataset 提供视频窗口、动作、本体状态、padding mask 和语言或缓存文本嵌入；build_inputs 做 VAE 编码并取首帧条件；视频与动作分别采样噪声/时间；MoT 前向输出两路预测；动作损失先对动作维平均，再按有效token求平均，结合时间权重和视频损失；trainer 更新两支 DiT 和可选本体编码器，冻结VAE/文本编码器，保存checkpoint。fastwam.py L285、L522、trainer.py L304

论文的 flow 路径应为：

xtc=(1−t)ϵc+txc,v∗=xc−ϵcx_t^c=(1-t)\epsilon^c+t x^c,\qquad v^*=x^c-\epsilon^c

原式(1)的 t, x 在PDF与LaTeX中有多余逗号；上式依据紧邻的路径定义做了明确校正。训练让模型预测从噪声到动作的速度，推理用式(2)做Euler更新。骨干当前 scheduler 用另一方向的 σ：噪声比例从1降到0，target为 noise - sample、步长为负。两者可通过 t=1−σt=1-\sigma 对齐，不能把论文正向速度直接塞进负向scheduler。scheduler_continuous.py L49–85

Fast-WAM 当前 attention mask 只允许动作读首帧video token；未来视频用于训练监督，不作为动作端可偷看的未来标签。这提供训练—推理一致性的结构依据。C³ache 本身既不改变训练可见信息，也没有证明其近似缓存完整保留这一条件化能力。

推理复现还缺什么

最少需要固定 Fast-WAM checkpoint、VAE/文本组件、dataset stats、对应动作映射与环境，设置10个真实采样时间点和32步horizon，再实现每episode独立的残差表。必须确认执行前缀长度、图像排列、环境reset、成功判定和seed一致。正文没有给精度、batch、CUDA/PyTorch版本、warm-up、同步计时、是否包含模型加载、文本编码、CPU仿真/动作执行时间；它明确纳入的只有完整推理管线及列举组件。

当前骨干默认 compile_action_infer=true，含编译优化和新变体，不能假定就是 C³ache 的 baseline。infer_action 函数默认采样20步，而本文实验10步；当前LIBERO配置 replan_steps=10 也不能倒推成 C³ache 实验执行长度。论文未给训练epoch、学习率、训练GPU时数、对应checkpoint哈希；这些缺项应由作者补齐，不用同类模型惯例填空。

10局限与对项目的借鉴

最可靠的适用范围是：多步动作生成、邻近块平滑、存在足够长的可缓存早期采样段、且愿意在验证集上手调refresh的策略。主要风险是缓存过期与尾部误差，尤其在长任务、操作阶段切换或视觉条件变化时。论文只给仿真benchmark和单骨干实验，不能扩写为在真实机器人、任意WAM或单步蒸馏模型上普遍有效。

当前项目 Metrotime 是论文档案站，包含静态HTML、清单和预览图，没有机器人策略模型或实时控制接口，因此不存在可直接插入的DiT缓存点。对本项目的具体价值是以“参数/采样预算/重复计算/计时口径”组织研究证据，并把R、video KV、跨去噪步cache的差别写清楚。本站没有因此修改训练或控制代码。

对未来模型工程的条件化建议：先在 prepare → action core → head 边界做最小残差缓存，在完整计算路径验证等价，再记录命中步是否真的得到最新条件。以成功率约束下的累计wall-clock为优化目标，同时监控p95单块延迟、缓存年龄与长任务表现。动态reset/refresh可以作为后续实验，但必须单独评估其判据成本与失败回退；不要把它包装成论文已有机制。
