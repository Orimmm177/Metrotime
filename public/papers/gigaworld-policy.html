01核心结论与证据范围

GigaWorld-Policy 的关键不是“机器人先想象一段视频，再从视频中找动作”，而是把依赖关系固定为当前观测与状态 → 动作 → 未来视觉变化。训练时，动作预测和视频预测共同更新同一个 Wan 2.2 5B 主干；部署时，因为动作分支从来不读取未来视频 token，可以删掉未来视频的 Transformer 计算，只保留动作流匹配采样。这是一种把世界建模监督留在参数中、把视频生成成本移出主要控制路径的设计。论文 §3、图3–4，PDF pp.4–7

作者报告 A100 上每次推理 360ms，Motus 为 3231ms，约 8.98 倍加速。真机四任务表中的平均值为 0.83 对 0.76，但真机采用分级评分、每 trial 最多五次尝试，不能直接当成“一次执行完整成功概率”。仿真附录 50 任务本次逐行复算得到 Clean 86.36%、Rand 85.04%，相对 Motus 的 88.64%、86.96% 略低。这支持性能与延迟的有利折中，不能写成所有设置下同时胜过 Motus。论文表3–4、8

最值得借鉴的机制是通过注意力的结构约束，使辅助任务在部署时可以移除；最应谨慎复述的数字是“95%提升”“7%提升”和“实时”。它们分别涉及基线不一致、百分点与相对比例、以及模型调用延迟与控制频率的区别。

02问题定义：让视觉未来监督动作，而不阻塞动作

输入、目标与可见信息

每个环境时刻 t，模型获取三路 RGB 图像 ot、本体状态 st、语言指令 l，输出长度 p=48 的动作块。训练样本还包含专家动作 at:t+47 与未来图像；推理不具备真实未来图像，只能从当前条件生成动作。语言不是自注意力 token 排列中的第五块，而是通过交叉注意力注入主干。§3.1–3.2

论文定义未来视觉采样间隔 Δ=12，在动作块覆盖范围内预测 K=⌊p/Δ⌋=4 个未来观测，对应 t+12,t+24,t+36,t+48，加当前帧共5个采样画面。这里 t 是环境时间，流匹配时间另记为 s；48 是动作条数，不是48秒，也不是去噪步数。具体控制 Hz、动作块实际执行多少步后重规划、通信和执行器延迟未在论文给出。§3.1、§4 implementation details

论文用动作隐表示 ct 连接两个条件分布：

(at:t+p−1,ct)~gΘ(·∣ot,st,l)
ot+Δ:t+KΔ~gΘ(·∣ot,st,l,ct)

这是对论文式(2)–(3)的简写，第二行表示稀疏采样序列。ct 的作用是让视觉预测受动作表征约束；不要凭符号另造一个价值头或额外规划网络。公开代码直接让未来视频 token 读取动作 token 的隐藏表示，没有独立命名为 c_t 的输出接口。

VLA 的动作损失较稀疏，作者希望视频生成提供密集的时空监督；双向视频—动作生成则让动作读取生成中的未来画面，带来计算成本和对视频误差的依赖；视频后接 IDM 又把完整预测放在动作前面。本文改的是信息依赖方向和训练/推理分工，并不增加搜索、奖励、候选轨迹打分或在线世界模型规划。作者称“physics priors”时，证据来自视频预训练和下游任务，不是显式物理方程或接触约束保证。

注意两类“未来信息”不能混淆：训练使用未来视频作为标签是合法监督；动作在推理前向依赖不可得的未来标签才是部署问题。双向联合生成也可能在推理生成未来变量，未必构成数据集切分意义的泄漏。本文的因果 mask 解决的是动作生成的计算依赖，不证明训练数据没有重复或跨集合污染。

视觉入口与语言条件

三视角先组合为一个画布，再用同一个预训练 VAE 编码当前画面和未来画面。当前画面产生 To，未来带噪 latent 产生 Tf。论文没有引入相机标定、深度重建或几何坐标变换；“共同画布”应理解为图像布局，不能等同于已对齐的三维世界坐标系。代价是每路视角的分辨率、裁切和布局会影响精细接触辨识。

原版代码实际将 cam_high → cam_left_wrist → cam_right_wrist 横向拼接；示例为每路宽256、高192，组合后宽768、高192。当前0.5时代的 GWP-0 配置改成宽320、高384的T形布局（上方主视角、下方两腕），与原版不同。本文的复现路线以原版横排为依据，不能把新布局无声移植到旧 checkpoint。原版 transform L168–202；新配置

语言使用预计算 T5 表征，经交叉注意力作用于各 token；原版示例截断/补齐到64个语言 token，T5预计算脚本与示例长度要统一。VAE 在原版 trainer 中冻结，编码采用 latent distribution 的 mode 并做均值/标准差归一化；文本 embedding 在离线预计算后读入，不参与该训练入口的梯度更新。trainer L29–42、L200–207

动作、本体状态与共享层

状态和动作先投影到主干宽度。论文写线性投影，原版实现采用 D → 128 → 256 → 3072 的三层 MLP，含 GELU；状态复用动作 encoder。输出端用逆向宽度的 MLP 返回动作空间，视频端用 patch projection 返回 VAE latent。共享的是 Transformer blocks 与 Q/K/V 投影，独立的是输入/输出模态接口；这里不是 MoE，也不是后续0.5的动作专家与视频专家。§3.2；trainer L50–69

原版示例模型动作维为16；AgileX 的 mask 暗示有效布局为两组“6个增量维度+1个绝对维度”，共14维，其余维度补齐。仅凭这段 mask 不能断言六个数一定是关节角或末端位姿，更不能补出角度单位、夹爪量纲、机器人坐标系和安全限幅。论文确认 PiPER 6-DoF 机械臂，具体数据字典仍是复现依赖。

视觉位置编码在论文中称2D图像网格编码，原版 WanRotaryPosEmbed 实际按时间、高、宽三轴构造 RoPE；状态/动作使用1D RoPE。它们随后按输入排列重排，不能直接共用一条无模态区分的位置序列。动作块内部不是48次离散自回归，而是整块连续流匹配。

为什么删掉未来视频仍能保留同一动作函数？解释：在每个 block，条件状态不依赖未来或动作，动作状态只依赖条件与动作。归纳到所有层，未来视频 token 没有路径影响动作输出。因此在相同参数、输入、流时间与数值实现下，删除这组 token 保持动作的理论依赖不变；浮点 kernel 切换仍可能造成微小数值差别，需要实际一致性实验确认。

另一方面，视频损失依然能训练动作相关表征。未来视频会读取动作隐藏表示，损失梯度可以沿这条读取路径回传，同时还更新共享主干。前向禁止未来影响动作，不等于反向禁止视频损失影响动作参数。论文没有提供视频梯度对动作表征贡献的直接测量，所以这是结构解释，不是单独验证过的因果结论。它约束潜在表示，也不等于在每个推理动作上显式检查物理可行性。

04一个样本怎样穿过网络

以“拿起扫码器并扫描目标物体”的某个时刻为教学例子，任务来自附录C，以下数据流不假装来自已下载的实际轨迹。

  1. 从同一轨迹读取当前三视角图像、状态、任务语言、随后48条专家动作；监督视频取偏移0、12、24、36、48。相机同步、数据 Hz 与状态时间戳必须由数据本身提供。
  2. 将三个视角按固定顺序裁切、缩放、横排。原版例子形成 [B,5,3,192,768] 图像批次，编码成时空 latent；精确 latent 维度由加载的 VAE 配置决定，不能直接把4个未来画面等同4个 latent 时间片。
  3. 取第一帧独立编码为干净参考 latent；未来 latent 加噪。动作归一化后同样加噪，当前状态保持干净。状态与动作经共享 MLP，视频经 patch embedding，全部投影到3072维。原版 trainer
  4. 排列为状态、当前视觉、动作、未来视觉，使用图4的块 mask。文本通过各层 cross-attention 进入，流时间通过条件调制进入；当前条件 token 的时间设为0，动作与未来块分配相同噪声时间。
  5. 动作头输出48条动作的速度场，视觉头输出 latent 速度场。与专家动作/未来画面构造的目标比较；VAE不更新，Transformer和动作接口更新。
  6. 部署时只保留状态、当前视觉和带噪动作进入 blocks，多步积分后反归一化、恢复增量参考，输出一整个连续动作块。真实控制器如何分段执行及何时回传新观测，论文未公开足够接口细节。

原版代码 shape 依据：示例16维动作、3072隐藏宽度，状态 [B,1,16]、动作 [B,48,16]，投影后对应 [B,1,3072] 与 [B,48,3072]。这反映 example 配置，不等于作者所有真机实验的维度；原版推理 pipeline 另有14维默认值，见复现章节。

05设计取舍：收益从哪里来，代价留在哪里

固定方向而不是双向融合。 双向融合可能利用未来生成对动作纠错，但也让部署不能直接删掉视觉未来。本文选择动作先行的结构，对推理成本更可控；代价是动作在同一次前向中不能再利用“想象到的未来”反向修正。若任务需要候选动作模拟、碰撞判断或规划，不能从本文自动推导这些能力。

共享大主干而不是小动作专家。 共享Q/K/V能让动作学习受视频先验影响，避免重新训练完全独立的控制网络。删去视频未来之后，剩余动作仍要通过5B级共享主干，故360ms不是“轻量控制器”或电机控制周期。后续0.5换成专家架构是另一篇工作，恰好说明原版还有活跃参数成本。

稀疏未来监督而不是逐帧预测。 48步动作配4个未来采样观测，减少相邻帧冗余并保留动作后果。表5中 Δ=12 最好，但这组实验保持动作 horizon 不变，只改采样密度；不能说它直接证明“更长预测时间范围更差”。过密时更多视觉计算、不同loss密度与优化难度可能共同变化。表5、§4.5

视频预训练后再适配具身数据。 Web视频带来视觉生成基础，具身视频使视角与接触交互更接近机器人，再用目标机器人轨迹学习接口。好处是把大规模无动作视频监督用起来；代价是约万小时数据与6000 GPU小时具身预训练，真实机器人少样本优势并不是总体低训练成本。

视频分支可选而非消失。 训练始终要承担视觉监督成本；若部署需要观察预测结果，可以恢复联合采样。论文还提到先动作采样、再重用KV生成视频，但原版主 pipeline 没有把这一顺序复用路径完整暴露出来。类名或 cache_context 不足以证明实现了论文描述的跨阶段KV复用。

流匹配目标及方向核对

按照论文式(6)–(10)，对动作或未来latent记干净变量为 x，噪声为 ϵ：

x(s)=(1−s)ϵ+sx,x˙(s)=x−ϵ

流时间 s~U(0,1)，从纯噪声走向数据；视频头以当前观测、状态、动作表征和文本为条件，动作头以当前观测、状态和文本为条件。两者分别回归速度场，后训练总体目标为：

Lall=Lvideo+5Laction

关键是未来标签不流入动作可读的条件块，而进入被屏蔽的未来块，并通过监督与共享参数影响学习。实际 trainer 给动作和视频使用同一批 sigma，噪声分别采样；它并非先生成完整干净动作再把动作输入视频网络，而是在联合去噪表示中连接两者。因而正文“predicted actions”应理解为动作表征的耦合，不宜画成必有独立完整动作生成阶段的串行训练。

原版代码写成相反的时间坐标：

xσ=(1−σ)x+σϵ,vσ=ϵ−x

令 s=1−σ 可解释速度符号相反，因此这本身不是数学错误。但代码对均匀随机数 u 再做 shift（配置值5）并取整：

σ=5u1+4u,τ=round(1000σ)

之后以 τ/1000 实际加噪；这与论文直接均匀 s 的训练分布不同。论文坐标变换解释符号，不能解释掉采样分布的区别。原版 trainer L95–104、L209–218

另一个确切差异是 loss reduction：原版主 trainer 计算两个全元素均值并返回，基类直接求和，所读路径没有动作系数5。视觉loss先用第一帧mask归零，再对包含首帧的整张量平均，而不是只除有效未来元素数；动作loss未使用 transform 输出的 action_dim_mask。补齐维度和有效时间占比会改变相对loss尺度。报告不把公开example的1:1与论文5:1静默统一，也不据此声称作者实验实际上用了错误权重。trainer L187–197；基类parse_losses L914–925

训练执行顺序可归纳为：按轨迹采样窗口 → 固定多视角布局与归一化 → 冻结VAE编码 → 当前参考替换为干净latent → 对未来和动作加噪 → 按块mask前向 → 双速度loss → 主干与动作接口反向更新 → 保存checkpoint/EMA。这是一条后训练流程；不包含RL、奖励模型、在线数据回流或测试时参数更新。

07推理与闭环：360ms究竟测了什么

论文动作路径从高斯噪声初始化48步动作，积分式(12)得到连续动作块：

da(s)ds=gΘ(a(s),s∣To,Ts,Tl)

积分方向为 s:0→1。原版公开 server 默认10个采样步、guidance scale=0、5个视频采样帧设置、48条动作；不开 return_images 时调用 action-only 路径。模型每层只送入状态、当前视觉、动作三个块；视频未来latent仍可能在准备阶段分配和patch化，但不进入主要Transformer blocks，也不执行未来视频的速度更新与VAE解码。因此“无需生成未来视频”成立，“完全不分配任何未来视频张量”不符合所读代码。原版 model L817–935；pipeline L242–327、L499–599

启用视频时，pipeline同时更新视频和动作，再经VAE解码视频。论文另给出的先动作后视频、重用动作去噪KV路线没有在这条公开调用链完整落实：cache_context("cond") 是框架上下文标记，所读注意力处理器仍重新投影当前Q/K/V，未见把上一阶段动作KV作为独立参数传入。不能把继承 CacheMixin 当作已验证跨请求记忆，也不能假设存在长期历史缓存。

原版状态/动作以 z-score 归一化。对需要增量的维度，训练目标相对窗口开始的状态，不是相邻动作的逐步差分：

δat+i,j=at+i,j−st,j

输出反归一化后，对这些维度加回同一个 st；夹爪样式的绝对维度保持绝对值。窗口首状态、动作统计量、mask和最终机器人控制语义必须一致，不能把输出当成48次累加的相邻增量。原版工具支持z-score/minmax，但example训练是z-score，不能直接换统计模式。原版transform L243–279；pipeline工具

闭环边界：论文描述执行动作后重新观察并重复，真机存在真实环境反馈；公开 inference_client.py 是读取离线数据的 open-loop 客户端，下一帧来自数据集，不来自执行预测动作后的环境。当前脚本的 REPLAN_STEPS=30 也是离线窗口步长设置，不是原论文真机重规划协议的证据。

延迟边界：A100 360ms 是一次模型推理报告值，算术倒数约2.78次调用/秒，并不等于每秒2.78条低层动作，也不等于每秒133条动作能按真实时间执行。论文没有完整披露360ms测量的batch、暖机、输入分辨率、采样步数、精度、主机传输与相机处理范围；公开server默认10步不证明该实验正好采用此设置。比较表中 π0.5 为225ms，本文360ms是其1.6倍延迟，因此“matches inference speed”应视为宽泛的同量级表述，不能写成同速。

特别需要建立两个检查：一是训练/推理预处理对同一个样本输出一致的状态和图像；二是固定噪声时添加、删除或扰动未来视频输入，动作输出是否保持理论不变。这比只验证模型能返回某个shape更接近本文的核心主张。

12适用边界与研究建议

Metrotime 是论文阅读档案网站，本报告不把它当成机器人模型项目，不虚构数据接口或训练接入点。以下是供后续WAM研究采用的条件化建议。

优先验证辅助视觉监督能否在你的控制任务中真正提高动作质量。 在同一主干、数据、动作归一化和训练预算下比较动作单任务、双向联合、本文单向联合三组；同时测动作成功、视频指标与实际推理延迟。若视觉质量提升但控制效果不提升，或收益只来自更多训练预算，应收回“世界监督改善动作”的机制解释。成本为多个匹配训练实验，证据目前来自表5/6和结构推导。

先证明裁枝等价，再做工程加速。 接入点是attention mask和采样入口，前提是每层条件token不读取未来、动作只读条件和自身，位置编码与时步不因删token变化。最小改动是提供joint/action-only两个同权重前向并固定初始噪声，对比每步动作速度与最终轨迹。若误差超过数值容差，先排查mask、normalization、位置索引和CFG，不能用速度收益掩盖行为变化。

把延迟对成功率的影响单独测出来。 使用同一checkpoint与控制器，人为加入匹配的等待时间或改变重规划周期，区分“策略更好”和“反馈更快”。测完成率、动作跟踪误差、过期观测比例及p95延迟。若延迟不敏感，论文对真机优势的解释不应直接迁移到你的平台；如果动作块执行已经异步，360ms对实际闭环的影响还取决于缓冲策略。

动作物理语义优先于张量维度。 比较14/16/32维接口时，要先建立坐标系、单位、绝对/相对、起始状态参考和夹爪含义的映射。最小实验是对真实数据做归一化—反归一化回环，检查每维误差与轨迹边界；若只是补齐维度却换了物理语义，应停止跨本体迁移的结论。该建议由两版公开代码的具体差异支持，未进行硬件验证。

保留论文版本与结果口径。 对Metrotime档案的直接价值是把“动作中心共享DiT”与后续MoT/AutoResearch版本分清，记录正文、附录、代码和权重的不同时间点。读者可据此比较结构，不会把新版本的85ms与本篇360ms混在同一条性能曲线上。

总体适用范围是有三视角观测、本体状态与动作示范、能承担视频主干训练成本的操作策略学习。论文没有验证移动全身控制、广泛跨本体零样本、力控安全、长时遮挡记忆或在线自主纠错；这些都需要额外数据、接口和实验。
