01概览：让视觉未来与动作共同生成

DreamZero 的重要变化，是把视频生成模型训练成可以直接输出动作的闭环策略。 它在 Wan2.1-I2V-14B 上增加本体状态与动作接口，让同一套 DiT 同时去噪未来视频和动作；历史来自真实观测，当前块的视觉与动作互相交互。执行后，真实画面替代想象画面进入 KV cache。这样，视频先验提供运动与场景演化线索，机器人数据负责把这些线索对齐到具体执行器。论文 §3，pp.6–9

作者在 AgiBot G1 的异地、未见物体评测中报告：已见任务平均进度 62.2%，未见任务 39.5%，分别高于最佳已预训练 VLA 基线的 27.4% 和 16.3%。这里的“超过 2 倍”主要是平均任务进度之比，不能改写为所有任务完整成功率翻倍。DROID-Franka 未见任务的完整成功率只有 22.5%，说明模型已经能迁移一些新动作，但距可靠完成开放世界任务仍有距离。图8–9，pp.13–14

最值得带走的三个机制： 共享主干把“未来会怎样”和“应该怎么动”放在同一次联合生成中；只缓存真实视觉历史，避免把错误动作或想象反复当成事实；Flash 通过训练噪声分布适配少步推理，让动作在视觉尚未完全清晰时也能收敛。相应代价是 14B 主干、双卡推理、有限历史和仍不可靠的精细操作。

02问题定义：零样本到底相对于什么

输入是语言指令、当前本体状态和可用的视觉历史；输出是未来一段视频与时间对齐的动作块。推理时没有真实未来画面。训练时未来视频与动作是监督目标，历史块采用干净观测进行 teacher forcing。目标是从多样、少重复的机器人经验中学到可泛化的运动，而不是只记住高频动作模板。

论文式(1)把联合策略解释为视频预测与逆动力学的组合。下面使用简化记号重述，并保留语言条件以避免把条件独立假设误写成一般恒等式：

p(O+,A+∣h,c,q)=p(O+∣h,c,q)·p(A+∣O+,h,c,q).

其中 h 为视觉历史，c 为指令，q 为当前状态，O+、A+ 是未来视频与动作。这是一种建模解释，不代表系统先跑一个独立视频规划器、再调用另一套逆动力学模型。 实际实现使用一个联合 DiT，在当前块内部不断交换信息。论文原式的 IDM 因子省略了语言条件；这可以理解为假设视觉计划已经承载任务信息，而不是证明任意联合分布都能去掉语言。§3.1，pp.6–7

“零样本”有几种不同口径。基础模型已经接受机器人训练：AgiBot 约500小时，Franka 使用 DROID，两种 embodiment 分别训练。新环境、新物体以及机器人训练集中缺少的新任务，才是主要 zero-shot 评测对象。网络视频预训练是否出现类似人类动作没有被逐条排除。因此它既不是完全没有机器人数据，也不是证明某个动作从未出现在任何预训练材料中。

视频迁移实验另有区别：向模型加入人类或 YAM 的目标任务视频后，这些任务相对于 AgiBot 动作数据 仍未见，但模型已经看过其视觉示范。30分钟 YAM 适配则使用新机器人的动作标签，属于 few-shot embodiment adaptation，不能合并为“仅凭视频零样本控制任意机器人”。

从观测到共享 DiT

视觉输入先按固定相机布局拼成单帧，再经过冻结的 VAE 编码。保留 Wan 的图像条件分支与文本编码器，能够继续使用原有图像到视频先验。语言经文本编码后作为条件；当前关节等本体状态通过 state encoder 进入主干；待生成动作先加噪，再经 action encoder 投影到与视频 token 可交互的表示。代码中的外层类虽然叫 VLA，其 backbone 是 identity，真正的大型视频主干位于 WANPolicyHead.model，不能据类名误读成“VLM 后接动作头”。代码：VLA 包装器、主配置

共享主干是 Wan 初始化的 causal DiT，而非两个独立的视频/动作专家。噪声视频经 patch embedding，动作与状态经各自投影后沿 token 维拼接；同块 self-attention 让动作与视频互相读取。文本及 CLIP 图像条件经 cross-attention 注入。干净视觉上下文另有一份表示，依靠 mask 限制可见范围。去噪结束，视频头恢复 latent，VAE decoder 可将其还原成图像；动作头输出连续动作，经过反归一化、相对量还原，才能交给控制端。

跟随一个样本：Franka 把马克笔放进盒子

以下是依据论文和 DROID 代码整理的解释性样本，不是本次机器人运行记录。

  1. 当前观测包含两路外部相机、腕部相机、7个关节位置与夹爪状态，指令是“把马克笔放进盒子”。预处理必须沿 checkpoint 的相机顺序、归一化统计量进行。
  2. 当前所读 DROID transform 把腕部图放在顶部并将宽度扩成两倍，外部左右视角位于底部两格。AgiBot 则是头部、左右手和一格黑屏的另一种布局。相同“三视角”数量不代表相机位置可随意交换。DreamTransform._prepare_video，L309–381
  3. 初始视觉写入 cache。对下一个1.6秒窗口采样视频噪声与24步 DROID 动作噪声；当前 state 和语言保持条件身份，不用真实未来动作作条件。
  4. DiT 在去噪中让带噪动作、当前未来视频和本体状态交互，并读取过去真实画面。动作不需要等待整个未来视频被解码成 RGB 才能输出。
  5. 动作从标准化相对关节量恢复成该次观测对应的绝对目标；夹爪走其自身字段。执行端选择前若干步，随后获得新画面、更新视觉历史，再重新预测。
  6. 若生成视频错误地计划把笔交到另一只手，动作可以与这个错误计划高度一致；“跨模态对齐良好”不等于“任务正确”。附录H的失败示例正是这种情况。

04注意力与缓存：为什么历史只保留视觉

查看原尺寸图（可横向滚动）

来源：论文图14，第21页；蓝色是 self-attention，橙色是缓存历史。图中的 Ck 表示条件画面，Zk 是待预测视频，Yk 是当前动作块。它不是完整源码状态 token 布局图。

跨块的因果性主要施加在视频历史上，当前块的视频和动作联合去噪。 当前块能够看过去干净视觉、自己的噪声视频、自己的噪声动作以及对应状态；它不能偷看同一块的干净未来视频，也不依赖先前生成的动作块作跨块历史。这个选择既为 KV cache 创造条件，也降低错误动作在历史中反复传播的机会。

官方代码将 clean image 与 noisy image/action/state 分开，CausalWanSelfAttention.forward 在 teacher-forcing 分支调用 _process_clean_image_only、_process_noisy_image_blocks 和 _process_noisy_action_blocks。后两个方法拼接的 K/V 包含“之前的 clean 画面 + 当前噪声视频 + 当前动作 + 当前状态”；当前干净目标不在可见片段中。这是静态 mask 路径核验，尚未用运行时 attention 测试覆盖每个可选分支。L820–952、L661–784

论文式(2)之后及算法1把历史集合写成过去视频和动作的二元组，但正文明确说“只对视频使用自回归”，图14与当前实现也支持视觉历史。报告据这些较具体的证据解释机制，保留公式符号与实现之间的差异，不据集合记号声称存在动作历史 cache。

真实观测怎样阻断误差积累

lazy_joint_video_action 初始阶段以无动作、无状态输入执行 update_kv_cache=True，写入真实视觉条件；当前块联合去噪时使用 update_kv_cache=False。下次调用把实际观察到的视频编码后写回，而不是把上次 video_pred 永久当成事实。函数也提供 latent_video 入口，调用方若传生成 latent 就会改变这一假设；本次核验的公开 WebSocket 主路径没有传它。L973–1191

语言变化、单帧重新开始或达到局部历史限制会重置当前帧索引，进而重建 cache；服务端还按 session_id 清理会话。跨 episode 使用同一个 cache 会混入旧任务信息，不能只在前端改 prompt 而忽略状态生命周期。

作者称这“消除”自回归误差积累，应按机制限定理解：它消除的是把预测画面不断回灌为历史这一条链路。错误动作已经改变环境、当块规划错误、观测延迟和有限历史仍然存在。论文也明确未专门评估只能依赖记忆才能完成的任务；有 KV cache 并不等于通过了长时记忆能力验证。p.8脚注2、§6

05联合流匹配：两个时间轴与真实损失

一个时间轴是机器人轨迹中的 chunk，另一个是 chunk 内的去噪进度。两者不能混用。为避免原文 K 同时被用于 latent 数和求和上限带来混淆，这里用 k 表示轨迹块索引，t 表示论文的去噪进度。

论文约定 t=0 为高斯噪声、t=1 为干净数据。视频 latent 和归一化动作在同一基础 timestep 上线性插值：

ztk=tkz1k+(1−tk)z0k,atk=tka1k+(1−tk)a0k,z0k,a0k~N(0,I).

同块视频与动作共享 tk，不同块可独立采样。共享的是噪声强度，不是两个模态使用同一个噪声张量。模型预测从噪声走向数据的速度；下面按论文式(3)重写，并显式分出目标速度以缩短公式：

vk=[z1k−z0k, a1k−a0k],L=E[1M∑k=1Mw(tk)‖uθk−vk‖2].

uθk 接收当前两模态的带噪输入、历史视觉、语言、状态和 timestep。梯度同时调整视频主干和动作接口，使动作监督能影响共享时空表征。未来画面不是额外标注的语义答案，而是密集的预测目标；对于只有视频的数据，只保留视频损失。

代码的时间方向相反，但不必然矛盾

FlowMatchScheduler 使用噪声占比 σ：

xσ=(1−σ)xclean+σϵ,vcode=ϵ−xclean,σ=1−t.

因此代码 target noise - sample 与论文 clean - noise 符号相反，在从高 σ 向低 σ 积分时是相容的；不能只比较减号就判断代码写反。add_noise、training_target 和 step 必须一起读。scheduler L18–90

还有两点需要区分。第一，代码均匀采样的是 schedule 索引，随后经过 sigma shift 映射；这不严格等于论文写的物理 t 上均匀分布。第二，视频损失先对通道与空间求均值，动作损失乘有效维 mask 与 has_real_action 后对 padded 维度求均值，再各自加权相加。它并非把所有视频/动作元素拼成一个向量后直接求相同平方范数。不同 padding 维度或视频-only 混合比例会改变有效权重。head L674–810

论文伪代码中的三处口径差异

  • 算法1 Flash 分支写 tvideo~Beta(7,1)，而正文与式(5)写 tvideo=1−η。在论文“0噪声端、1数据端”的约定下，前者偏向干净视频，方向相反；本报告采用正文、图5和式(5)一致的后一种定义。
  • 算法2在真实 clean context 写入处标 t=0，但其去噪循环又采用论文的 0→1 约定。公开实现的 clean cache 使用代码噪声时间0，可解释实现行为，但不能使论文伪代码自身的符号自动一致。
  • 算法1把参数更新写在 chunk 循环内部；正文强调轨迹级更新，代码一次 forward 对多个块求总损失，由 Trainer 更新。复现应依据实际训练调用，而不是照抄算法排版。

这些是阅读与复现时需要消歧的地方，不是本次运行证明的训练故障。

06DreamZero-Flash：动作先收敛，视频可以暂时模糊

查看原尺寸图（可横向滚动）

来源：论文图5，第9页。横轴采用论文去噪进度，小值代表高噪声；不能与代码 sigma 轴直接同向比较。

基础联合训练总让视频和动作处于相近的噪声水平。当推理只剩一两步时，视频可能仍很粗糙，而控制需要已经可用的动作。这形成训练与推理条件分布的差异。Flash 没有增添另一个动作专家，而是在最后训练阶段让两者的噪声日程独立，使动作学习在不够清晰的视觉 latent 上完成预测。§3.2.5、附录D.3

η~Beta(7,1),tvideo=1−η,taction~U(0,1),E[tvideo]=1−78=18.

这里高噪声的是当前待生成视频；已经写入缓存的真实过去画面仍是干净上下文。因此不是把机器人观察到的一切都随机污染，而是让动作头不强依赖“当块未来已经完整成像”。它属于改变训练条件分布的适配，论文没有把它定义为 teacher-student 蒸馏。

公开版本已包含 decouple_video_action_noise 和 decouple_inference_noise，但默认都关闭；视频 Beta 默认(3,1)，不是论文示例(7,1)。训练先采样噪声比例，再换成降序 schedule 的索引，之后还会经过 shift；不能把配置的 Beta 均值直接当实际 latent 的干净比例。动作独立采样在代码中按 action 序列位置产生，和论文以整个 chunk 写一个 timestep 的简化记法也有粒度差异。head配置、采样分支

推理端可把视频 sigma 的终点重新映射为 video_inference_final_noise（默认0.8），而动作走完整去噪日程。两种 scheduler 仍在同一个联合模型中调用；“单步动作”不等于把视觉 token 从主干删除。head L1200–1305

表3是这项机制最直接的证据：同为单步，普通 DreamZero 为52%任务进度，Flash为74%，恢复22个百分点；四步基线83%，仍比Flash高9个百分点。两种单步推理都是150ms，Flash的作用主要是相同少步预算下改善质量，不是在单步基线上再次减半耗时。该结果只在 table bussing 任务给出，不能外推为所有任务无损。

07数据与训练：多样性如何变成监督

数据范围和切分

一个窗口怎样组成

附录C使用每块2个视频latent，默认4个块。AgiBot视频5FPS、动作30Hz，每块48步；DROID视频5FPS、动作15Hz，每块24步，都对应1.6秒。论文同时写最大上下文8个latent等价33原始帧，约6.6秒。按所读实现，VAE保留初始条件帧，再对后续32帧压缩，常见张量组织为1个初始latent + 4×2个后续latent；“8”指后续块，不能把初始帧也算进去却仍声称总数8。33/5是样本计数口径6.6秒，首末帧时间差则是32/5=6.4秒，二者应标明定义。

DROID有效动作为7关节加1夹爪。数据配置仅对 joint_position 使用相对动作：每个24步chunk减该块锚点的观测关节状态，夹爪不按同一规则相减。模型输出后必须加回正确锚点，而不是对相邻预测动作做累加积分。单位与关节顺序依赖数据元信息和机器人驱动，本次没有读取真实机器人标定，不能为所有 embodiment 宣称统一坐标语义。dataset L1057–1129、policy反变换 L539–604

分阶段训练和参数更新

基础视频预训练来自Wan权重，不是本次机器人训练从随机参数重建视频生成器。论文分别在AgiBot、DROID上各训练100K步、global batch128；所有DiT blocks、state/action encoder与action decoder更新，文本、图像编码器和VAE冻结。所谓 from-scratch DreamZero 指没有额外机器人预训练，不是随机初始化14B主干。作者试过LoRA但报告效果次优，未给足够数字建立普适排序。

训练数据先采样轨迹窗口、对齐视觉与动作、构造相对量与归一化、生成有效维mask；然后编码视频与语言，为每个chunk构造噪声，调用teacher-forcing mask并计算联合loss。BaseTrainer.compute_loss从VLA.forward → WANPolicyHead.forward取得loss后更新；保存配置、metadata与checkpoint。所读 create_val_dataset 返回None，不能仅看训练loss下降就声称得到论文闭环能力。trainer

当前代码的 droid_training_full_finetune_wan21.sh 确实选择全参数训练、Wan2.1路径、33帧、24步动作、2 latent/块、4块；但默认200K步，global batch默认为GPU数×每卡batch，默认4，不是论文100K/128。学习率1e-5、weight decay1e-5和warmup0.05是脚本配置证据，论文未据此给出完整实验配置。复现时必须保存Hydra合并后的最终配置，不能把命令名当配置证明。完整训练脚本

Flash一般在主训练之后作为最终阶段使用；其训练步数、最终论文checkpoint对应的噪声参数组合仍不完全明确。跨机器人video-only混训和新机器人有动作微调是另外两种阶段，不能全部拼成同一个“通用训练循环”。

08推理与执行：吞吐、时延和控制频率分开

可用推理需要模型权重、编码器权重、数据统计量、相机映射和机器人动作接口。当前官方服务路径是 ARDroidRoboarenaPolicy.infer → GrootSimPolicy.lazy_joint_forward_causal → VLA.lazy_joint_video_action_causal → WANPolicyHead.lazy_joint_video_action。服务端转换相机键、累计视觉历史，policy做归一化，模型联合采样，policy反归一化并把相对关节值还原为绝对值，最后返回动作矩阵。服务端、policy

公开server首调用用1帧，后续累计4帧，不足时重复补帧；模型中还有满足VAE块长度的重复处理。这样的补帧不等于获得更多真实时间信息。移植时应核查相机采样时间戳和推理调用间隔，不能仅保证张量长度正确。

当前head构造函数设16个scheduler步、CFG scale5、sigma shift5和固定seed1140。NUM_DIT_STEPS调节计算mask，不等于scheduler步数；DYNAMIC_CACHE_SCHEDULE=true会按相邻预测视频速度的余弦相似度决定跳过前向。实现检查的是guided视频速度，跳过时一并复用缓存的视频与条件动作速度。视频使用CFG组合，动作更新直接用conditional prediction，不能说两模态都做完全相同的CFG。head L180–228、L943–970、L1275–1305

有三种不同的缓存：视觉历史KV缓存跨推理调用存在；文本/图像cross-attention缓存服务同一上下文；DiT velocity缓存只在当前去噪循环复用，当前调用新建。混淆三者会误判何时必须重置，以及省掉的是历史编码还是当前模型前向。

论文的异步执行要求控制端继续执行最新动作，同时模型根据新观测生成下一块，并按时间戳消费动作。它解决等待推理造成的停顿，但不自动解决过期动作、跨chunk不连续或相机延迟。公开仿真client实际是缓存动作块、用完默认8步后再调用服务，不能将这条同步示例路线当成论文完整异步控制栈。eval client L28–115

错误视觉计划会被准确执行

附录H展示画线任务变成左右手传笔、烤面包任务在开烤箱前先拿起面包，执行随错误想象一起偏离目标。作者据此认为视频规划是重要瓶颈；本报告把它理解为诊断线索。两例可视化并不能证明“所有失败都来自视频”，attention或视频动作相似也不能替代对模型因果作用的干预实验。论文还承认亚厘米插入、装配等高精度操作不足，以及约6秒历史限制。

当前版本的关键差异与复现影响

  1. 路径与训练预算。 README的droid_training.sh在本快照不存在，实际可选脚本包括droid_training_full_finetune_wan21.sh与LoRA/5B路径。Wan2.1脚本默认200K、batch4；论文100K、batch128。它也没有简单透传任意末尾参数，不能随手追加max_steps=100000就假定覆盖成功。
  2. Flash不是默认模式。 训练和推理解耦开关均默认关闭，Beta默认3；基础head实际设置16个solver步，yaml中num_inference_timesteps:4不能单独证明当前执行4步。必须检查最终对象、env和checkpoint配置。
  3. 公开实现已有后续扩展。 仓库包括Wan2.2-TI2V-5B；论文规模消融文字称Wan2.1-I2V-5B。没有足够证据认定新5B路径就是论文消融模型。
  4. 发布速度与论文速度不同。 README写GB200约0.6秒/H100约3秒，论文最优150ms另需模型、系统与硬件组合。论文平滑filter在本快照主路径未找到。
  5. 动作与视角兼容性。 DROID相机布局、相对关节锚点和metadata都是模型输入协议的一部分。把三张任意图或另一个机器人的同维动作塞进接口不构成有效迁移。
  6. 状态信息是静态检查。 本次没有导入和运行完整模型，未测量实际张量、延迟或内存。潜在配置差异不能直接推断论文实验使用了错误设置。

关键结果复现

优先DROID公开数据与checkpoint路径，再考虑需要AgiBot原始采集资料的结果。复现必须区分基础100K/128训练、单任务50K后训练、video-only共训练10K以及Flash最后阶段；固定训练种子、采样序列、过滤规则、checkpoint选择和评测初始状态。保存每条rollout原始分数与判定依据，分别汇报任务进度、完整成功率、每任务均值和不确定性。

论文§4.1/附录C对视频时间轴已有说明，但完整学习率日程、Flash阶段训练预算、量化校准材料、全任务成功判定及某些基线内部实现仍需要补齐。AgiBot原始多样数据在论文中是计划发布状态，本次未验证其完整开放情况；不能据数据画廊宣称训练集已可完全复现。

公平对比与消融

最有价值的验证是把视频质量、动作质量和执行系统拆开控制：在相同数据/steps/控制端下比较coupled与decoupled训练；给Flash、普通模型相同solver步数；对cache reuse分别测执行成功率和视频质量；把相同动作规划放到同一延迟补偿策略下比较。记录预热后p50/p95端到端延迟、GPU型号与数量、精度、实际DiT前向数、执行步数和缓存长度，而不只报告倒数Hz。

对多样性实验，保持总小时数和训练预算，再分别控制任务数、场景数、对象数与重复率。对video-only迁移增加“仅继续训练原数据”的等步数基线。对AR/BD补充jerk、动作块边界跳变和相机—动作时间对齐误差。以上均为建议实验，未被本次实际完成。

12边界与面向 Metrotime 的研究建议

Metrotime是论文阅读档案，没有机器人状态流、控制器或模型训练接口。本篇收录带来的直接价值是可追溯的模型比较材料：把联合生成、视觉历史缓存、噪声解耦、数据多样性分别连到证据，避免只记住“14B、7Hz、zero-shot”三个标签。

优先级 / 建议 依据与最小落点 验证与回退条件
高：研究笔记统一时间语义 本文同时有5FPS、15/30Hz、1.6秒chunk、150ms推理；在本报告表格明确单位与端到端范围 后续论文能逐项比较；缺失值标未知，不用公式倒数冒充实测控制率
高：区分论文机制与发布默认值 当前脚本、Flash开关、相机拼图均与简述存在差异；在代码导航固定commit和差异 读者能定位原始文件；版本变化后保留历史身份，不覆盖成“始终如此”
中：记录生成正确性与动作一致性的区别 附录H展示错误计划被准确执行；报告把失败证据纳入结论 以后有干预实验再提高因果证据强度，不把示例当统计结论
中：用研究假设组织Flash比较 联合基础模型＋高噪声视觉条件适配；可与后续少步WAM论文按相同步数比较 仅在训练预算、硬件和任务口径匹配时排序，否则并列呈现

如果将来在独立机器人项目中尝试机制，优先做相机/动作时间对齐与真实观测cache回写检查，再考虑Flash后训练；前提是已有可用联合WAM与闭环评测环境。出现chunk跳变、噪声条件错配或任务成功率下降时回到已验证的多步基线。这是条件化研究建议，不是对Metrotime添加机器人实现的计划。

当前证据最强的是：特定多样机器人数据和异地任务设置下，视频预训练联合动作模型获得显著更高的任务进度；最需要继续验证的是：更广泛真实任务的可靠性、低成本部署、精细接触、长时记忆，以及Flash在完整任务集上的质量—延迟曲线。
